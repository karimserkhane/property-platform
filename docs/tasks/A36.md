# A36 — Images satellite servies comme fichiers cachables

**Pourquoi** : chantier 6 de la [feuille de route technique](../engineering/ENGINEERING_ROADMAP.md), toujours « À faire ». La lecture `imagery` intègre chaque aperçu en base64 dans le JSON : `"image_url": "data:image/png;base64," + …` dans `evidence/projects/queries.py:38` (`imagery_scenes`). Mesure du 23/10 : 857 Ko presque incompressibles (649 Ko en gzip) à chaque affichage de la vue imagerie, sans cache navigateur possible par image.

**Dépendances** : A08 (cache de lecture et ETag).

## Critères d'acceptation

- [ ] Route d'image par scène (identité durable, `ETag`, `Cache-Control` privé comme les autres lectures `/preview`), relais web à trois lignes ; la lecture `imagery` renvoie une URL au lieu des octets.
- [ ] Attribution, licence et droits de chaque scène inchangés ; une scène dont la publication est refusée n'est pas servie.
- [ ] Mesure avant/après de la vue imagerie dans la feuille de route ; chantier 6 marqué terminé.
- [ ] Contrat régénéré ; tests API (PostGIS) et web.

## Indications techniques

`api/parcels.py` (`/imagery`), `evidence/projects/queries.py` (`imagery_scenes`), relais `relayPreview` du site. Les médias de projet ont déjà une route de flux (`api/project_media.py`) : reprendre son patron.
