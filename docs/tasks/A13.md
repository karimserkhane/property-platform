# A13 — Parcours navigateur en CI

**Pourquoi** : A05 livre `checks-e2e` en local, contre la base locale. La CI GitHub ne
les exécute pas encore : elle n'a ni API PostGIS ni données.

**Dépendances** : A05.

## Critères d'acceptation

- [ ] Jeu de données de démonstration reconstruit par migrations et pipelines (aucun dump
  versionné), suffisant pour chaque parcours : parcelles de Reem, quelques fiches dont
  une hiérarchie relue, une langue RTL.
- [ ] Job CI : PostGIS, API, jeu de démonstration, image `checks-e2e` ; traces et
  captures publiées comme artefacts en cas d'échec.
- [ ] Durée maîtrisée et aucun parcours marqué ignoré faute de données.

## Indications techniques

Réutiliser l'étape `e2e` du `Dockerfile` web et la configuration de
`apps/web/playwright.config.ts` ; voir [E2E.md](../engineering/E2E.md).

## Décision attendue du propriétaire

La CI GitHub n'a ni base partagée ni accès aux sources, et le rejeu A04 ne fonctionne
qu'à partir d'octets capturés. Un jeu de démonstration « reconstruit par migrations et
pipelines » exige donc des octets de source disponibles en CI. Le dépôt n'en versionne
aucun aujourd'hui (seulement des registres revus : sources, relations, catalogues).
Les parcours ont besoin de parcelles de Reem (AD-SDI/Onwani), de rues et bâtiments
(OSM), et de fiches projets lues sur des sites de promoteurs ou d'annonces, dont les
pages sont protégées par le droit d'auteur et leurs conditions d'utilisation.

Options :

1. **Captures réelles versionnées** : un petit paquet de rejeu (manifeste A04 et octets
   d'une dizaine de captures : quelques parcelles de Reem, un extrait OSM, deux ou trois
   fiches dont une hiérarchie relue) sous un dossier dédié avec provenance et licence par
   fichier, rejoué par l'importateur A04 dans la base PostGIS jetable de la CI. Fidèle et
   sans réseau, mais recopie dans l'historique Git (dépôt privé) des pages tierces.
2. **Captures ouvertes réelles + fiches synthétiques marquées** : octets réels seulement
   pour les sources sous licence ouverte (OSM, ODbL avec attribution ; AD-SDI si sa
   licence le permet), et fiches projets fabriquées pour le test, signalées comme
   telles, jamais importées hors de la base CI. Aucun contenu tiers protégé, mais des
   données inventées passent par les importateurs (à réserver strictement à la CI).
3. **Paquet privé téléchargé par la CI** : le paquet de l'option 1 reste hors Git et la
   CI le lit depuis un stockage privé (secret GitHub, par exemple R2). Rien de tiers
   dans le dépôt, mais compte cloud, secret et coût potentiel à approuver ; le jeu
   n'est plus reconstructible depuis le dépôt seul.

Recommandation de Claude : option 1 limitée au strict minimum des parcours, avec
provenance, licence et date de capture par octet, ou option 2 si Karim préfère ne
versionner aucun contenu de promoteur. Aucun code n'est écrit avant la décision.
