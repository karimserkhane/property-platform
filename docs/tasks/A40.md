# A40 — Corriger les vulnérabilités critiques relevées par la première analyse

**Pourquoi** : la première analyse Grype d'[A38](A38.md) (3 novembre 2026, run CI 41668475256 de la PR #63) trouve des vulnérabilités critiques pour lesquelles un correctif est publié, dans ce que la plateforme exécute aujourd'hui :

| Cible | Composant | Correctif |
| --- | --- | --- |
| Image `node:26.11.1-trixie-slim` (web, contrôles) | Node 26.11.1, faille exploitée activement (liste KEV, EPSS 99e centile) | Node 26.12.1 |
| Image `python:3.14.8-slim-trixie` (API, ingestion, contrôles) | CPython 3.14.8 | 3.14.10 |
| Lockfile pnpm | `next` 16.4.0 (2 avis critiques) | 16.4.1 |
| Lockfiles uv | `certifi` 2026.7.22 | 2026.10.18 |
| Image `postgis/postgis:18-3.6` en service | paquets Debian (brotli, OpenSSL, curl, Perl, glibc…) | digest plus récent du même tag |
| Images tierces | Playwright 1.64.0 (Firefox), Tailscale 1.104.1 (bibliothèque Go), text-embeddings-inference | versions ou digests plus récents |

L'étape bloquante du job `vulnerabilities` est signalée sans faire échouer la CI tant que ces versions ne sont pas corrigées : sinon toutes les PR seraient rouges.

**Dépendances** : A38 (analyse, Dependabot, digests).

## Critères d'acceptation

- [ ] Node et Python montés au correctif dans tous les fichiers alignés par [TOOLCHAIN.md](../engineering/TOOLCHAIN.md) (`.node-version`, `.python-version`, Dockerfile, CI, guide) ; `next` et `certifi` à jour dans leurs lockfiles. Les PR Dependabot correspondantes peuvent servir de base.
- [ ] Digests des images de base et des bases de données mis à jour ; pour PostGIS et PostgreSQL, conteneurs recréés seulement avec l'accord de Karim (base partagée), volumes conservés.
- [ ] Images tierces : version corrigée retenue ou exception motivée et datée dans `.grype.yaml` (par exemple Playwright, limité aux contrôles e2e).
- [ ] `continue-on-error` retiré de l'étape bloquante ; job `vulnerabilities` vert ; contrôles Docker et CI verts.
