# A04 — Contrôle de reconstruction depuis les pipelines

**Pourquoi** : Exigence du propriétaire : toutes les données doivent pouvoir être recréées par les pipelines Prefect.

**Dépendances** : A03.

**Découpage après essai réel** : A04 livre le contrôle et le runbook. La reproduction
des anciens protocoles est suivie en [A11](A11.md), celle des anciennes versions
d'interprétation en [A12](A12.md). L'objectif global de reconstruction complète
reste ouvert tant que ces écarts ne sont pas résolus ; un flow rouge n'est pas
présenté comme une reconstruction réussie.

## Critères d'acceptation

- [x] Runbook : base vide → migrations → flows dans l'ordre → contrôle d'inventaire.
- [x] Flow `rebuild-check` qui rejoue les captures archivées dans une base jetable et compare les comptes par table.
- [x] Liste explicite de ce qui n'est pas reconstructible (décisions opérateur, médias privés) et de leur sauvegarde.

## Indications techniques

S'appuyer sur `pipeline_inventory.py` et le journal `row_revision`.
