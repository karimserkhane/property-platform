# A24 — Droits de chaque source dans toute l'API et sur la carte

**Pourquoi** : seules la fiche projet et la page « Sources et licences » montrent les
droits d'une source. Les autres réponses de l'API donnent une URL et un nom sans
licence, et le site les cite sans statut : la carte et ses parcelles, le contexte public,
le marché ADREC, les références, les alentours, les zones de marche, l'imagerie,
l'annuaire et l'historique de livraison. Karim veut voir le statut de toutes les
données affichées ([A23](A23.md)).

**Dépendances** : A22. A23 n'est pas requise : l'API lit les droits par
`source_rights.public_rights`.

## Constat (29/10)

- API : 26 points d'accès ; 2 donnent `rights` (fiche projet et registre).
- Site : 15 composants citent une source sans son statut ; 12 dans `features/atlas`,
  plus l'historique de livraison, les médias et la carte du quartier de la fiche projet.
- `project_snapshot.source_rights_status` vaut `restricted` sur les 1 666 lignes, quel
  que soit le registre ; l'API l'envoie à côté de `rights` (`rights_status`).

## Critères d'acceptation

- [ ] Chaque provenance de l'API (parcelles, carte, contexte public, ADREC, références,
  alentours, zones de marche, marché par district, imagerie, recherche dans les preuves,
  annuaire, historique de livraison) porte `rights`, comme les sources d'une fiche.
- [ ] Les zones de marche et autres calculs locaux prennent les droits de leur source
  d'origine, comme `evidence.data_rights`.
- [ ] Le site affiche le statut sous chaque source citée, avec le composant
  `SourceRights` ; textes dans les 16 langues.
- [ ] `source_rights_status` retiré de la base et de l'API, ou dérivé du registre.
- [ ] Contrats régénérés ; tests API et web ; contrôles CI verts.

## Indications techniques

`api/parcels.py`, `api/public_context.py`, `api/accessibility.py`,
`api/evidence_search.py`, `api/projects.py` ; `features/projects/evidence.tsx`
(`SourceRights`) ; `features/atlas/*`.
