# A14 — Contrôle réel du rejeu géographique : identités et divergence revue

**Pourquoi** : [A11](A11.md) livre les adaptateurs de rejeu des anciens protocoles
Onwani (`onwani-reem-v1`) et Overpass (`reem-map-v1` à `v3`, `district-map-v4`).
Leur effet sur les données réelles ne se mesure qu'avec ce code déployé dans
l'ingestion, par un `rebuild-check` ([REBUILD.md](../engineering/REBUILD.md)).

**Dépendances** : A11 (fusionnée et déployée dans l'ingestion).

## Critères d'acceptation

Découpée le 24 octobre 2026 : la suite exige un contrôle réel avec le code de cette
tâche déployé, donc après sa fusion. Les anciennes identités OSM, les liens dépendants
et les écarts restants passent dans [A15](A15.md).

- [x] `rebuild-check` réel après déploiement d'A11 : les cinq acquisitions refusées du
  dernier contrôle A04 (`9d04f812`, `9d9d0656`, `d7b5f4bc`, `29a909a9`, `ece1a59f`) sont
  rejouées ; l'écart de 2 431 parcelles est expliqué (doublons remplacés par une
  réparation revue) et rendu sémantique par la politique `identity`.
- [x] Parcelles et zones : identités actives exactes, remplacements justifiés un à un
  par les réparations revues ; aucune fusion par nom/proximité ni champ inventé.
- [x] Comptes d'observations par étape dans le manifeste et le rapport (diagnostic).
- [x] `d7b5f4bc` qualifié ; divergence inscrite à un registre revu, acceptée seulement
  si le rejeu concorde avec `29a909a9` sur les mêmes octets, sans masquer une
  quarantaine nouvelle ni désactiver la détection d'une couverture manquante.

## Indications techniques

- Point attendu : `d7b5f4bc` avait été mis en quarantaine (1 093 éléments) puis
  `29a909a9` accepté une minute plus tard avec les **mêmes octets** (SHA-256
  `06a6dedd…`). Le mappage actuel leur donnera vraisemblablement le même statut :
  divergence d'interprétation à qualifier (lien avec [A12](A12.md)), pas une perte.
- Lancer le contrôle selon REBUILD.md, jamais deux en parallèle ; ne jamais modifier
  la base en service.
