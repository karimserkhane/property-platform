# A16 — Version de cache des tables de provenance par source

**Pourquoi** : Depuis A08, une réponse en mémoire n'est relue que si sa famille de tables change. Mais `evidence.capture` et `evidence.ingestion_run` reçoivent une ligne à chaque collecte planifiée (chaque minute en local) et sont lues par presque toutes les routes qui citent leurs sources : ces lectures sont encore relues après chaque collecte, même d'une autre source.

**Dépendances** : A08.

## Critères d'acceptation

- [ ] Pour `capture` et `ingestion_run` (et seulement si la mesure le justifie, d'autres tables partagées), une version plus fine que la table : par exemple par source ou par jeu de données lu, relevée sans liste déclarée à la main, avec le même repli sûr qu'A08.
- [ ] Exactitude démontrée par tests : une collecte d'une autre source garde le corps ; une capture ou un run de la source lue l'invalide, y compris une transaction en cours validée plus tard ; une exclusion l'invalide toujours.
- [ ] Mesure avant/après sur la base locale (familles et fréquence d'invalidation de `district-map`, `market-map`, liste des parcelles) notée dans ENGINEERING_ROADMAP.

## Indications techniques

Voir `api/read_cache.py` et la section « Version par famille de tables » d'[ENGINEERING_ROADMAP](../engineering/ENGINEERING_ROADMAP.md). Piste : la source d'une ligne de `capture`/`ingestion_run` est dans `after`/`before` du journal ; un index d'expression ou une colonne dérivée journalisée permettrait de lire « dernière révision de cette source ». Ne jamais ignorer les insertions : certaines routes lisent « le dernier run réussi » d'un jeu de données.
