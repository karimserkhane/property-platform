# B11 — Frise d'avancement d'un projet sur sa fiche

**Pourquoi** : le pilier P2 du [plan concurrentiel](../product/PLAN_CONCURRENTIEL_20261023.md) promet « une frise par projet » qui réunit ce qui dit si le chantier avance vraiment. Les éléments existent mais restent dispersés : lectures d'avancement ADREC dans la section « Vérification » ([B05](B05.md)), signal satellite dans sa propre section ([B07](B07.md)), dates de livraison annoncées successives sur la page promoteur ([B03](B03.md)), frise des paiements dans le simulateur ([C02](C02.md)). Un acheteur doit aujourd'hui les rapprocher lui-même.

**Dépendances** : B05, B07, B03. Les permis de construire s'y ajouteront si [B10](B10.md) en autorise la collecte ; la frise n'attend pas B10.

## Critères d'acceptation

- [ ] Une frise datée sur la fiche projet : lectures d'avancement déclaré (date d'inspection), signaux satellite (dates des deux scènes, niveau, jamais un pourcentage), dates de livraison annoncées successives et leur source, livraison constatée si elle existe.
- [ ] Chaque point ouvre sa preuve (capture, date, droits) ; nature affichée (déclaré, observé, annoncé) ; un vide reste un vide.
- [ ] Contradictions visibles sur la frise (par exemple livraison annoncée passée sans livraison constatée, avancement déclaré en recul).
- [ ] Lisible sur téléphone, 16 langues, RTL ; parcours Playwright.

## Indications techniques

Lectures déjà exposées par la fiche (`verification.register_readings`, `construction_activity`, historique de livraison) : composer côté `publication` ou côté web sans recalcul ni nouvelle collecte ; contrat régénéré si une lecture est ajoutée. Règles : [DELIVERY_HISTORY.md](../engineering/DELIVERY_HISTORY.md), [CONSTRUCTION_ACTIVITY.md](../engineering/CONSTRUCTION_ACTIVITY.md).
