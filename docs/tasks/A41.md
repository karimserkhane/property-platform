# A41 — Plusieurs agents en parallèle : tableau généré et réservation atomique

**Pourquoi** : `BOARD.md` est le fichier le plus modifié du dépôt (108 fois depuis le 23/10), à la main, dans chaque PR : c'est la première source de conflits. Et rien n'empêche deux agents de prendre la même tâche au même moment ([audit](../engineering/AUDIT_STRUCTURE_20261108.md)).

**Dépendances** : aucune.

## Critères d'acceptation

- [ ] `BOARD.md` est généré depuis l'en-tête des fichiers de tâches, à l'identique du tableau actuel ; une PR ne le modifie plus.
- [ ] Un workflow le regénère sur `main` après chaque fusion qui touche une tâche.
- [ ] Une commande donne les tâches prenables et une autre réserve une tâche de façon atomique : deux agents ne peuvent pas réussir la même réservation.
- [ ] La CI refuse un en-tête de tâche invalide ou une dépendance inconnue.
- [ ] `AGENTS.md` et `AGENT_WORKFLOW.md` décrivent le nouveau déroulé.
