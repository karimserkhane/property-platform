# A18 — Captures sous licence non qualifiée dans le dépôt public

**Pourquoi** : la décision A13 du 25/10 (option 1) autorise une copie interne de
captures réelles « dans le dépôt privé ». Or `karimserkhane/property-platform` est
**public depuis sa création** (9/10), si bien que `fixtures/demo-replay/` est publié de
fait. `selection.json` le dit lui-même : « Not a licence to republish. »

**Dépendances** : A13.

## Constat (27/10, lecture seule)

Paquet ajouté par `e20867c` (25/10) : 44 fichiers, 6,4 Mo, présents sur 14 branches
distantes dont la branche de référence, dans les PR fusionnées depuis #25, et bientôt
dans `main` avec la PR #37.

| Source | Captures | Taille | Conditions |
| --- | --- | --- | --- |
| `www.aldar.com` : pages des projets Gate et Gate & Arc | 2 | 0,9 Mo | Non qualifiées. Pages HTML complètes (textes commerciaux, mise en page) : le contenu le plus nettement protégé. |
| `searchservice.properties.aldar.com` : fiche de communauté Gate | 1 | 632 o | Non qualifiées ; donnée brute. |
| `adrec.gov.ae` : registre, Faya Al Saadiyat | 1 | 8 Ko | Non qualifiées ; registre public. |
| `onwani.abudhabi.ae` (DMT) : parcelles, quartier, communautés et rues de Reem | 40 | 4,2 Mo | Non qualifiées ; service ArcGIS public sans licence de réutilisation publiée connue. |
| `overpass-api.de` : OpenStreetMap | 1 | 1,2 Mo | ODbL 1.0 : redistribution permise avec attribution. |

Exposition mesurée (statistiques GitHub, 14 derniers jours) :
- aucun fork, aucune étoile, aucun abonné ;
- 49 vues par un seul visiteur unique et des clones par un seul cloneur unique par jour,
  ce qui correspond au propriétaire, aux agents et à la CI ;
- seul référent : `github.com`.

Ces statistiques ne montrent ni les robots ni les archives tierces. Une copie déjà
faite ailleurs ne se récupère pas.

Coût de la CI : environ 33 runs exécutés par jour depuis le 23/10, à 13 minutes
facturables chacun (4 jobs arrondis à la minute), soit environ 13 000 minutes par mois.
C'est gratuit tant que le dépôt est public : le run 40386809111 affiche 0 ms
facturable. Sur un dépôt privé, l'offre gratuite inclut 2 000 minutes par mois (à
confirmer sur la page de facturation du compte). Le 26/10, GitHub a déjà refusé six
jobs pour un problème de paiement ou de limite de dépense.

## Décision du propriétaire

**Décidée le 27/10 : option 2, avec purge de l'historique** (voir le journal).

Options présentées :

1. **Repasser le dépôt en privé** (réglage GitHub, par Karim).
   - Aucun code ; la décision A13 redevient exacte.
   - Au rythme actuel, la CI dépasserait environ 6 fois le quota gratuit : minutes
     payantes, ou CI fortement réduite.
2. **Paquet dans un dépôt privé séparé, lu par la CI.**
   - Karim crée `karimserkhane/property-platform-demo-replay` (privé) et une clé de
     déploiement en lecture seule : partie publique sur ce dépôt, partie privée en
     secret Actions du dépôt public. Aucun agent ne manipule la clé.
   - Le job `e2e` récupère le paquet avec un second `actions/checkout` dans
     `fixtures/demo-replay/`, à un commit figé dans le dépôt public, pour qu'un
     changement de paquet reste visible en revue.
   - Dans le dépôt public, `fixtures/demo-replay/` est ignoré par Git ;
     `export_demo_package` et les lancements locaux utilisent un clone du dépôt privé
     à cet emplacement.
   - Les captures réelles restent rejouées par les importateurs actuels, sans coût :
     les minutes restent celles d'un dépôt public.
   - Limites :
     - le paquet ne se reconstruit plus depuis le dépôt public seul ;
     - une PR venant d'un fork n'a pas le secret, et son job `e2e` échoue
       explicitement (aucun fork aujourd'hui).
3. **Captures ouvertes réelles et fiches synthétiques** (option 2 d'A13).
   - OSM reste réel ; les pages Aldar, ADREC et les réponses Onwani sont fabriquées
     pour le test, marquées comme telles, jamais importées hors de la base CI.
   - Ni secret ni coût, mais plusieurs jours de travail : il faut des géométries de
     parcelles inventées pour les parcours carte.
   - Les parcours ne vérifient plus les importateurs sur des octets réels.

Sous-décision, pour les options 2 et 3 : **purger l'historique**.
- Sans purge, les octets restent téléchargeables à `e20867c` et dans les PR, et le
  retrait ne fait qu'arrêter la publication de nouvelles copies.
- La purge (`git filter-repo` sur ces fichiers) exige :
  - de forcer la mise à jour des 14 branches, dont la branche de référence de Codex
    (accord explicite de Karim, fenêtre coordonnée avec Codex) ;
  - de réaligner les PR ouvertes (#30, #31, #37, #38, #40) et les worktrees locaux ;
  - de demander au support GitHub de retirer les références des PR et les vues en
    cache (procédure GitHub de suppression de données sensibles).

En parallèle, quelle que soit l'option : qualifier les conditions d'Onwani (DMT) et
d'ADREC. Si une licence ouverte les couvre, ces captures peuvent redevenir publiques
comme OSM. Les pages Aldar restent hors du dépôt public dans tous les cas.

**Recommandation de Claude : option 2 avec purge, maintenant.**
- Elle tient la décision A13 (captures réelles, copie privée), sans coût ni perte de
  fidélité des parcours.
- L'option 1 rendrait la CI payante.
- L'option 3 coûte plus de travail et teste les importateurs sur des données
  inventées.
- La purge n'a jamais été aussi peu chère qu'aujourd'hui : dépôt de 18 jours, aucun
  fork, aucun visiteur extérieur mesuré. Son coût grandit à chaque branche.

## Indications techniques

Voir [A13](A13.md), [E2E.md](../engineering/E2E.md), `infra/local/compose.e2e-demo.yaml`,
`.github/workflows/ci.yml` (job `e2e`), `evidence/rebuild/demo_package.py` et
`fixtures/demo-replay/selection.json`. `load_demo_package` vérifie le SHA-256 de chaque
octet : une capture allégée ou réécrite n'est plus une capture réelle et relève de
l'option 3.

Ordre retenu :

1. Karim crée le dépôt privé, la clé et le secret. Aucun agent ne voit la clé privée.
2. Le paquet actuel est poussé dans le dépôt privé.
3. Une PR adapte le dépôt public :
   - second `actions/checkout` avec `repository`, `ssh-key` et `ref` figé
     (par exemple dans `fixtures/demo-replay.ref`), vers `path: fixtures/demo-replay` ;
   - `.gitignore`, retrait du dossier, documentation.
   Les agents clonent le dépôt privé avec leurs identifiants Git habituels.
4. Fenêtre de purge, une fois cette PR fusionnée :
   - Codex et les autres sessions poussent tout et s'arrêtent ;
   - réécriture sur un clone miroir neuf (`git filter-repo --path fixtures/demo-replay
     --invert-paths`, ou `git filter-branch --index-filter` faute de Python sur l'hôte) ;
   - mise à jour forcée de toutes les branches, puis vérification sur un clone neuf.
   Chaque agent repart ensuite des branches réécrites : fusionner une ancienne branche
   locale réintroduirait les octets.
5. Karim demande au support GitHub de retirer les références des PR et les vues en
   cache.

Les images et caches CI ne contiennent pas le paquet : l'image API ne copie que
`apps/api/src`, et les caches Actions ne gardent que les dépendances uv et pnpm.
