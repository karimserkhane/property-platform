# F05 — Fin des imports de l'émirat : Madinat Al Riyad et AAM

**Pourquoi** : Découpée de [F04](F04.md) le 27/10/2026. Le réimport de Madinat Al Riyad exige le plafond AD-SDI de 50 000 identifiants livré par F04, donc sa fusion et le redéploiement de l'ingestion ; l'import AAM, lancé pendant F04, attendait encore dans le runner Prefect.

**Dépendances** : F04 (plafond AD-SDI, profil de couverture de l'émirat).

## Critères d'acceptation

- [ ] Madinat Al Riyad réimporté par le déploiement manuel `adm-parcels-adsdi-districts` une fois l'ingestion reconstruite depuis la branche de référence ; résultats et quarantaines notés.
- [ ] Résultats de l'import AAM (`aam-parcels-adsdi-districts`, flow run `sage-peccary` lancé le 27/10, ou un nouveau lancement s'il a échoué) : districts importés, parcelles créées, quarantaines et géométries invalides.
- [ ] Mesures de l'explorateur, des tuiles, de l'index par zone et de la recherche relevées après ces imports et comparées à celles de F04 dans `ENGINEERING_ROADMAP.md` (« Import ADM ») ; index sur `code` ajouté seulement si la recherche le mesure nécessaire.

## Indications techniques

Le runner d'ingestion sert un flow à la fois (`limit=1` dans `deployments.py`) et prend les exécutions dans l'ordre de leur heure prévue. Les files minute (fonds de carte et zones de marche) accumulent du retard pendant un import long ; le 27/10, `sage-peccary` attendait derrière environ 90 minutes de ces files. Un lancement manuel peut donc démarrer avec beaucoup de retard : vérifier son état avec le client Prefect plutôt que de le relancer.
